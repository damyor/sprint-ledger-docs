CSV export

Reference · updated 17 September 2026 (app version 2.6.0)

Sprint Ledger exports two files for spreadsheets and BI tools: every sprint of a board, one row per sprint, and one sprint, one row per issue. The export is on the project's settings page, which a project's administrators and Jira administrators can open: Space settings (Project settings on some sites) → Apps → Sprint Ledger, section Export. The dashboard gadget links to it.

Exporting

  1. Choose the board: the project's tracked boards that use sprints.
  2. Choose what to export: Every sprint of the board, or one of its started sprints.
  3. Choose the number format: 1.5, with commas between columns, or 1,5, with semicolons between columns, which is what a spreadsheet in much of continental Europe expects. It starts on the format your browser uses; pick the other one when the file is for someone else.
  4. Press Download CSV. The file is built in your browser and saved like any download.

Every sprint of a board

File name sprint-ledger_<board>_all-sprints.csv. One row per started sprint, oldest first, with the gadget's numbers:

ColumnHolds
Sprint, Sprint id, StateThe sprint's name, ID and state (active or closed)
Start (UTC), End (UTC)The sprint's start date; the completion date of a closed sprint, or the planned end of the active one
Committed, Added after start, Removed, Completed, Carried overIssue counts, as defined on How Sprint Ledger counts
Say/do, Scope changeRatios, for example 0.875: completed divided by committed, and added plus removed divided by committed. Format the column as a percentage to read them as the gadget shows them. Empty when nothing was committed
Committed estimate, Added estimate, Removed estimate, Completed estimate, Carried over estimateThe same five in the board's estimate. For a board estimated in time the headings end in "(hours)"
Completed outside, Completed outside estimateIssues that were already done when the sprint started and still done at the close, which count neither as completed nor as carried over (completed outside), and their estimate. The last two columns, so that a spreadsheet built on the earlier ones keeps working

One sprint

File name sprint-ledger_<board>_<sprint>.csv. One row per issue that counted in the sprint:

ColumnHolds
Issue key, Summary, Issue type, SubtaskThe issue as Jira shows it now; Subtask is TRUE or FALSE
ScopeCommitted, Added after start, Removed, or Added then removed
Added at (UTC), Added by (account id)When the issue first joined the sprint (before the start, for a committed issue) and the account that added it
Removed at (UTC), Removed by (account id)When it was taken out and by whom; empty unless it was removed
Estimate at start, Estimate at closeThe estimate when it entered the sprint (at the start for a committed issue) and at the close, or when it was removed. "(hours)" for time estimates
Status at closeThe issue's status when the sprint closed
Completed, Carried over, Completed outsideTRUE or FALSE, at most one of them TRUE; for the active sprint they are provisional until it closes. Completed outside is the last column

Who added or removed an issue is the person's Atlassian account ID rather than their name, because showing names would need an extra permission every installed site would have to approve. An administrator can turn off storing account IDs on the admin page; the two columns are then empty for changes made afterwards.

The file format

  • UTF-8 with a byte order mark, the marker Excel looks for to read accented and non-Latin text as UTF-8; lines end in CRLF; quoting follows RFC 4180.
  • Dates are YYYY-MM-DD HH:MM:SS in UTC; true and false are TRUE and FALSE; counts are whole numbers and estimates have up to two decimals.
  • A summary or a name that a spreadsheet would run as a formula (starting with =, +, - or @) is written with an apostrophe in front, so opening an export can never run one.
  • In Google Sheets, use File → Import; the separator is detected. For Power BI, Get data → Text/CSV.

What each person gets

Summaries and issue types are read from Jira as the person exporting, so an issue they cannot see in Jira is left out of the one-sprint file, and the page says how many were left out. The counts in the per-board file come from the app's records and are the same for everyone who can open the page.
